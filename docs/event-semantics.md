# P0 事件语义

## 事件信封

每个事件必须包含：

| 字段 | 语义 |
| --- | --- |
| `schema_version` | 事件契约版本，P0 固定为 `1` |
| `project_id` | 项目/隔离域，跨项目事件拒绝投影 |
| `event_id` | 来源范围内稳定且不可复用的幂等键 |
| `event_type` | 使用 `领域.过去式动作` 命名 |
| `source` | 消息、任务、日历、文档、人工或测试场景 |
| `source_ref` | 可审计的外部来源引用，不保存为推导结论 |
| `actor_id` | 行为人；系统事件允许为空 |
| `occurred_at` | 业务事实发生时间，必须包含时区 |
| `received_at` | OrgPilot 收到时间，必须包含时区 |
| `payload` | 与 `event_type` 对应的严格结构 |

未知字段会被拒绝，避免调用方拼写错误被静默吞掉。

## P0 事件类型

| 事件 | 核心语义 |
| --- | --- |
| `member.registered` | 在项目域内注册可引用成员 |
| `task.created` | 创建正式任务状态和依赖边 |
| `task.workflow_changed` | 变更任务系统中的正式流程状态 |
| `task.health_reported` | 创建来源明确的任务健康声明 |
| `commitment.made` | 创建机器可检查的 actor/target/predicate/value 承诺 |
| `commitment.superseded` | 显式终止旧承诺，可关联替代承诺 |

## 顺序、幂等与冲突

P0 按场景声明顺序回放：

- 完全相同的 `event_id` 重投不会重复改变状态；
- 相同 `event_id`、不同内容被视为数据损坏；
- 同一成员对同一任务的新健康声明 supersede 旧声明；
- 不同成员的冲突声明不会互相删除；
- 任务依赖必须引用已存在任务，且依赖图不得成环。

真实 Webhook 的乱序缓冲、持久化事务和并发写入属于后续阶段，P0 尚未实现。

## 承诺的结局

承诺只由事件推进，投影是事件日志的纯函数。一个 `active` 承诺在匹配事件（目标、谓词、取值都对上）
到达时结算：

| 结局 | 何时写入 |
| --- | --- |
| `fulfilled` | 匹配事件的 `occurred_at` 不晚于 `due_at`，或承诺没有 `due_at` |
| `broken` | 匹配事件的 `occurred_at` 晚于 `due_at`：事做完了，承诺的时间没守住 |
| `superseded` | 收到 `commitment.superseded` |

- 比较用业务时间 `occurred_at`，不用墙钟，所以同一份日志回放结果相同；也不用 `received_at`，
  消息晚到不算人晚交。恰好在 `due_at` 那一刻达成算按时；
- 「迟到但完成」不单设状态：`broken` 说的是承诺，完成与否看任务自己的状态，任务照常记为完成；
- 只有 `active` 的承诺会被结算，结算后不再变化；结算时 `last_update_at` 记为该事件的 `occurred_at`；
- **尚未实现**：过了 `due_at` 却一直没有匹配事件的承诺仍停在 `active`。发现它需要时间推进，
  属于 M1-8 / M1-10，设计见待写的 ADR-0014。`at_risk` 目前也没有任何写入方。

## LLM 边界

P0 场景直接提供结构化事件，不做自然语言提取。未来 LLM 只能把非可信消息转换为
待验证的结构化声明；它不能：

- 修改官方任务状态；
- 删除来源或冲突证据；
- 决定自己是否需要审批；
- 直接调用飞书写接口。
