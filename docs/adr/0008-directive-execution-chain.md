# ADR-0008: Event-Sourced Directive Execution Chain

- 状态：Accepted
- 日期：2026-08-29
- 关联：ADR-0007（意图路由层）、docs/upgrade-plan-open-organization.md（柱 2）

## 背景

ADR-0007 解决了指令的「识别」：PM 的「告诉Alice，必须在明天下午5点之前完成」被分类为 `directive` 并携带目标/任务/时间提示。本决策补上「执行与传达」：指令必须真正送达目标成员、跟踪确认与完成、未响应自动催办与升级——否则识别只是日志里的一个标签。

## 决策

1. **事件溯源，不建旁表**。新增五个类型化事件：`directive.issued / acknowledged / completed / reminded / escalated`，由投影器落到 `OrgState.directives`。重启恢复、审计回放、幂等去重全部复用既有事件账本机制，零新增存储表。
2. **独立 DirectiveManager，不塞进 CaseLedger**（对升级方案初稿的修订）。协调案例（CaseLedger）语义是「风险驱动的拓扑协调」，指令是「发布者驱动的工作传达」——二者状态机来源不同，混入会污染风险案例的语义与升级策略。指令链保持事件溯源 + 人工门禁的内核原则，但生命周期独立管理。
3. **下达前槽位收敛**（复用 ADR-0007 的 hints）：目标成员缺失 → 追问；目标成员不存在 → 拒绝下达；负责人唯一任务自动绑定、多任务 → 追问指定；「上午12点」类歧义时间 → 追问（中午 12:00 还是凌晨 00:00）；非特权角色（pm/lead 之外）下达 → 明确拒绝并引导走 PM。
4. **回复拦截语义克制**：仅显式确认关键词（收到/好的/明白/马上处理…，≤40 字）触发 `acknowledged`，仅明确完成表述（完成/搞定/已交付，且无否定/受阻词）触发 `completed`；其余回复原样走正常抽取管线，不误伤、不臆测。
5. **传达与升级**：指令经 adapter `SEND_DIRECTIVE` 私聊送达（沙箱与真实飞书同路径）；每条消息摄入时顺带超时清扫——超过 `ORGPILOT_DIRECTIVE_REMINDER_MINUTES`（默认 60）未确认自动提醒目标，超过 `ORGPILOT_DIRECTIVE_ESCALATION_MINUTES`（默认 1440）未确认向发布者升级；PM 亦可一键手动催办全部未确认指令。
6. **相对时间以团队参考时区解析**：指令截止时间解析锚点必须先转到 `ORGPILOT_TIMEZONE`，与抽取管线的时区裁定一致（UTC 存储时间戳不得作为相对时间锚点）。

## 后果

- 正：PM 指令从聊天话语变成可审计的工作项（下达→确认→完成全事件留痕，时间线可视化 📩✅🏁⏰🚨）；未响应有自动提醒与升级兜底；权限门禁为后续任务创建/改派审批链提供同构范式。
- 负/已知边界：确认与完成的判定基于关键词，误检面小但存在（完成表述被否定词否决时按普通汇报处理）；同步会话进行中，目标成员回复优先走探针路径，指令确认会被延迟（记录为已知限制）；中文真实姓名路由依赖成员目录扩展（规模化里程碑）。
