# ADR-0003：LLM 结构化声明抽取、防幻觉证据锚定与权限边界

- 状态：Accepted
- 日期：2026-08-26

## 背景

在 P0 和 M1 阶段，OrgPilot 只接收预定义、结构化的 `OrgEvent`。然而，真实组织中的研发与管理人员使用的是口语化、含糊且充满相对时间的自然语言消息（例如：“支付 SDK 报错，排查需要到明天下午 5 点”）。

引入大语言模型（LLM）进行文本理解是必然选择，但若无严密约束，容易导致：
1. **幻觉引文**：LLM 捏造不存在的事实或歪曲陈述者原意；
2. **越权篡改**：LLM 越过官方任务流程，直接将任务标记为完成或阻塞；
3. **时序漂移**：未能基于消息发生时戳解析“明天”、“周五”，导致绝对时间错乱；
4. **评测不可复现**：依赖在线 API 导致 CI/CD 产生网络波动、费用和非确定性。

## 决策

1. **确立坚固的 LLM 权限边界（Zero Direct Mutation）**：
   - LLM 只能提取来源明确的声明对象（`TaskHealthClaim` 和 `Commitment`），绝对不能直接修改官方任务状态（`TaskState.workflow_status`）；
   - 所有 Claim 必须附带 `confidence` 置信度，并由独立规则引擎和投影器进行状态融合与冲突保留。

2. **Schema 强类型结构化输出契约**：
   - 基于 Pydantic v2 的 StrictModel 定义 `ExtractionResult`，约束字段类型与取值范围；
   - 禁止非受控自由文本解析，统一采用 JSON Schema 强类型约束。

3. **防幻觉证据反查锚定（Grounding Verifier）**：
   - 提取结果必须包含 `source_quote`（原文直接引文）；
   - 提取引擎强制校验 `source_quote` 是否为原始用户消息的严格真实子串。若存在虚构引文，系统自动扣除置信度或拒绝入库。

4. **显式时间锚定（Temporal Normalization）**：
   - 提示词显式注入消息发生基准时戳 `occurred_at`（带时区）；
   - 将“明天下午”、“本周五下班前”等相对时间表达式归一化为 ISO 8601 带时区绝对时间戳。

5. **Provider-Agnostic 接口与双轨评测架构**：
   - 抽象 `LLMClient` 统一协议；
   - 提供 `MockLLMClient` 与 `RecordedReplayClient`，保障本地开发与 CI/CD 测试具备 100% 确定性与零成本回归；
   - 支持通过 `OpenAICompatibleLLMClient` 接入真实在线大模型。

## 后果

正面影响：
- 实现了从自然语言消息到结构化事件的无缝桥接；
- 从机制上杜绝证据凭空伪造；
- 评测流程可完全离线回放，指标量化透明；
- 保持了整个协调内核的事件溯源与不可变性。

代价与限制：
- 口语化复杂的代词指代和极度模糊的陈述可能需要上下文多轮补充；
- 相对时间解析依赖上下文参考时戳的准确性。
