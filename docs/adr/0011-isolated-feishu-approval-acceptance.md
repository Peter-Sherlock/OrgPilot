# ADR-0011：隔离的单审批卡验收

日期：2026-09-04。状态：已实现，离线验证；真实 L3-A 尚待授权与验收。

## 问题

L2 已验证私聊单文本收发。审批卡还需要验证卡片格式、真实按钮回调身份、审批状态及持久化
发送记录。通用业务网关会在审批通过后继续执行任务或通知，超出一次测试卡片的授权范围。

## 决策

提供 `orgpilot feishu-l3-approval`：

1. `--preview` 显示固定卡片，不加载配置、不创建验收目录、不连接平台。
2. 真实运行要求 `--confirm-single-card`、全新 `feishu-l3-...` 标识、30–300 秒窗口，
   演示注入关闭、环境写闸关闭。连接就绪后给出随机精确挑战，由匹配私聊用户绑定唯一 open_id。
3. 使用 `ApprovalManager` 建立本轮测试审批。仅包含无业务任务参数的合成提案；同意/拒绝
   只改变该测试审批状态，永不调用 `consume()`，没有后续任务执行器。
4. 使用独立 SQLite `SqlOutboxStore` 先持久化单卡命令，再用条件 UPDATE 原子占用一次额度。
   `pending / attempts=0 → held / attempts=1 → delivered`；只有平台成功码与消息 ID
   齐备后才能标记 delivered。异常或取消保留 held，自动 due 查询不返回它。
5. 唯一卡片使用固定说明和“同意测试／拒绝测试”按钮；发送能力仅调用一次 `send_card`。
   不使用通用 outbox 重试调度器，也不启动业务网关、LLM、任务/指令操作。
6. 回调必须匹配 SDK 提供的操作者 open_id、context.open_message_id，以及按钮 value 中的
   run_id、approval_id、随机 nonce；拒绝缺失字段、伪造身份、别的卡片、重复或过期回调。
7. 首次有效选择落盘后关闭业务受理窗口，只返回一次 toast 响应；留 1 秒响应宽限后退出监听器。
   不替换卡片、不追加文本。宽限并不构成 toast 已送达/已展示的证明。

## 证据及数据

`var/feishu-acceptance/<run-id>/` 必须全新，已有目录拒绝启动，也没有恢复命令：

- `report.json`：时间、计数、ID 的 SHA-256 截断指纹、平台接受/未知、审批选择、关闭结果。
- `outbox.db`：真实 SQL 发送账本，但目标为固定合成别名，payload 仅为验收标识及测试标记；
  完整 open_id、消息 ID、挑战码、回调 nonce 均只保存在当前进程内存中。
- `user-confirmation.json`：在线验收后可单独保存用户可见确认；不得改写机器报告伪造自动证据。

held 的 attempts 表示已经占用的单次额度；进程可能在真正 HTTP 请求前退出，所以不能据此
断言已经送达。held 计入待处理数量，必须核对用户界面和本轮报告，不能自动重放。

## 验收与后续

离线必须证明：一个目标、一张卡、身份/卡片绑定、同意和拒绝、重复/过期拒绝、审计失败
阻止发送、已占用额度的并发唯一性与 SQLite 重开后保留、未知结果不重试、无业务任务变化。

线上 L3-A 通过要求：一条精确挑战、一次卡片 API 接受、独立 outbox delivered/attempts=1、
一次正确身份回调及持久化选择、确认关闭、用户看到卡片并确认点击结果。
`user_visible_confirmed` 和 `callback_response_confirmed` 均不由工具推断。

这是审批卡与审批决策的隔离验收，不覆盖通用 GatewayService 的状态重放、完整业务事件事务、
审批后任务更新、通知扇出或生产恢复。后续任务更新与指令催办分别限定目标、次数并独立授权。
此方案沿用当前 SDK 的单进程单监听器边界；SDK 升级需要重新执行生命周期离线回归。
