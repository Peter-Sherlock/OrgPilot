# 项目资料问答（`/项目`）使用说明

> 对应 [ADR-0015](adr/0015-github-project-context-sync.md)（M2-0 首版）。本功能默认关闭；
> 所有开关见文末配置表。首版为单仓库、只读资料接入，不写 GitHub、不修改任务状态。

## 它能做什么

接入一个 GitHub 仓库的指定范围后，成员可以在私聊里发送：

```
/项目 <问题>
```

机器人将**只依据已接入的项目资料**回答：

- 项目目标、术语（如"联调"的定义）、交付约定（含原文引用与出处段落）；
- 已接入的工作记录：Issue 状态与负责人、PR 合并事实、review 记录、普通评论（保留为作者陈述）；
- 正式任务状态（只读展示 workflow_status / owner / deadline / dependencies，与资料分开标注）。

资料不足、互相冲突、来源已失效时，回答会明确列出缺口与冲突，不会用模型常识补出负责人、
交付时间或验收标准。PR 合并只能证明合并；"可联调 / 已上线"在没有接入部署证据时不能确认。

## 它不能做什么

- 不修改任何任务、事件、审批或 Case；`/项目` 是纯只读入口，不影响探针、待答 claim 与 `/同步`。
- 不执行资料中出现的指令（包括"执行命令 / 修改任务"类文字），不访问范围外链接或路径。
- 不联系其他成员；澄清只会回复提问者本人。
- 同一条消息只对应一次查询：重复投递复用原结果，不重复消耗预算。

## 回答里有什么

每条事实都带出处行（段落定位 + 修订标识），并附"资料水位"（各类资料覆盖状态）。
查询会经历有界的主动查阅（搜索 → 沿关联补读 → 读取原文），预算与停止原因见 ADR-0015
第 7.5–7.6 节；预算耗尽或无进展时用确定性模板给出已知事实与缺口，不强行拼凑完整答案。

## 接入步骤（管理者）

1. 建立绑定：目标仓库（稳定 repository_id）、分支、Markdown 路径白名单、
   Issue 范围（milestone 和/或显式清单）、补充 PR 清单、资料维护人。
2. 登记项目共享名单：只有名单内的成员可以提问；每次查询都会校验。
3. 首次导入按绑定范围读取并发布"资料代次"；之后通过 Webhook 与补查保持更新。

开启同步后，应用启动受管的收件箱 worker：新绑定首次尝试范围导入；签名校验通过的通知
持久化后即确认，由 worker 串行读取和发布。`retry_wait` 到期后自动继续，不依赖下一条通知。
重启会恢复 `processing` 记录并实际消费；关闭先停止接收与 worker，再关闭模型客户端和数据库。
初次平台读取失败会留下未就绪 / 不完整状态，需手动补查或后续通知恢复，不在轮询中无限重试初次导入。

## 配置开关

| 环境变量 | 默认 | 说明 |
|---|---|---|
| `ORGPILOT_PROJECT_QA_ENABLED` | `false` | `/项目` 入口总开关 |
| `ORGPILOT_GITHUB_SYNC_ENABLED` | `false` | 资料同步总开关（开启必须配 webhook secret） |
| `ORGPILOT_GITHUB_WEBHOOK_SECRET` | 无 | Webhook HMAC-SHA256 验签密钥 |
| `ORGPILOT_GITHUB_TOKEN` / `ORGPILOT_GITHUB_REPO` | 无 | 真实读取凭据与 `owner/name`；缺省为仅接收模式 |
| `ORGPILOT_GITHUB_RECHECK_ENABLED` | `false` | 定期补查（仅刷新资料） |
| `ORGPILOT_GITHUB_RECHECK_INTERVAL_SECONDS` | `1800` | 补查间隔 |
| `ORGPILOT_PROJECT_QA_ONLINE` | `false` | 在线生成（需 LLM 凭据；离线为确定性脚本策略） |
| `ORGPILOT_PROJECT_QA_MAX_SPEND_USD` | 无 | 单个问题的费用上限，在线开启必须为正数 |
| `ORGPILOT_PROJECT_QA_INPUT_USD_PER_MILLION` | 无 | 管理者配置的每百万输入 token 保守预算单价，在线必填 |
| `ORGPILOT_PROJECT_QA_OUTPUT_USD_PER_MILLION` | 无 | 管理者配置的每百万输出 token 保守预算单价，在线必填 |

费用单价由接入者核实并配置，代码不猜供应商价格。在线请求使用完整 UTF-8 请求字节数加协议
余量作为保守输入界限，并核对供应商返回的用量；脚本模式的字符估算不能授权在线请求。
探索、一次格式修复和最终归纳共享同一持久账本。超时或结果未知时保留该次最坏预留；
重新发送同一消息不会返还用量，且复用前仍检查当前请求者、问题身份、绑定授权和资料版本。

只读资料 worker 的唤醒、重试和可选补查只刷新资料，不启动业务协调轮次、截止日催办或成员通知。

关闭 `PROJECT_QA_ENABLED` 或 `GITHUB_SYNC_ENABLED` 即停止对应功能；既有业务表与事件日志
不受影响，资料表独立保留（ADR-0015 §8 的关闭与回滚边界）。

## 已知边界（首版）

- CI / Checks / 部署、Release、PR 行内评审线程、图片 / PDF、跨仓库遍历未接入；
  相关问题只能得到缺口说明。
- 普通自然语言消息不自动使用项目资料（冻结意图提示词不变）；后续 R1 需以新提示词版本
  单独开启并对照评测。
- 在线生成质量与真实 GitHub 同步为独立验收项，当前离线能力由
  `evals/project_context/` 冻结样例锁定（见开发日志 M2-0 C6）。
